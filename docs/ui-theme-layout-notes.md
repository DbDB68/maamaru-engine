# まあ丸 UI 主题与布局备忘

这份文档记录面板的视觉主题候选、可复用设计语言和布局研究方向。它不是固定规范，主要用于避免灵感散落在聊天记录里，并给后续主题换皮提供共同地基。

## 当前共识

- まあ丸首先是可重复操作的本丸工具，但不需要长成普通企业后台。
- 主题可以大胆玩颜色、纹理、字体、边框和动效，不必固守现有配色。
- 深色本身不是问题；需要保证背景、正文、状态色和强调色之间的关系清楚。
- 所有主题共享功能结构、语义状态和响应式规则，避免维护多份独立前端。
- 主题可拥有有限的布局性格，例如分区形状、信息密度和装饰位置，但不能改变操作含义。
- 动效要服务于切换、按压、运行、成功和失败反馈，并支持 `prefers-reduced-motion`。

## 主题候选

### 1. 千禧年日系像素

当前优先完善的基础主题。

- 浅蓝灰工作区、亮黄色顶栏、米白卡片。
- 硬边框、硬阴影和像素对齐的按压位移。
- 借鉴 JRPG 对话框、状态条、选择箭头和有限色板。
- 不必照搬深紫色动漫像素示例；可同时保留浅色版，并为未来深色版复用组件语言。
- 参考：[Pixel Anime](https://www.stylekit.top/zh/styles/pixel-anime)、[俏皮野兽派](https://www.stylekit.top/zh/styles/neo-brutalist-playful)、[Memphis](https://www.stylekit.top/zh/styles/memphis)。

### 2. 浮世绘数字风

适合本丸题材的正式换皮候选。

- 米白和纸底、靛蓝框架、朱红选中态、少量金色重要操作。
- 青海波、朱印和刷痕只作为局部装饰，不让操作区变成画展。
- 采用纯色色块、强轮廓和硬边阴影，避免玻璃态和柔光。
- 参考：[Ukiyo-e Digital](https://www.stylekit.top/zh/styles/ukiyo-e-digital)。

### 3. 枯山水侘寂

安静、低刺激的高完成度主题方向。

- 控制同时出现的信息量，强调留白、展开和收起。
- 使用不完全规则的纸面、石灰与墨色层次，但保持文字对比度。
- 适合长时间挂机查看，不追求强烈装饰。

### 4. 少女漫画

原本容易被误解为单纯粉色，实际拥有鲜明的日系漫画语言。

- 樱花粉 `#ffb7c5`、淡粉白 `#fff5f7`，辅以浅紫和淡金。
- 可使用网点纹理、花朵角框、缎带标题、多角星光和少量蕾丝边。
- 漫画分格可成为该主题的有限布局变体。
- 樱花和闪光应集中在标题、空状态和成功反馈，避免遮挡密集配置。
- 参考：[Shoujo Manga](https://www.stylekit.top/zh/styles/shoujo-manga)。

### 5. 剧团犬咖喱拼贴

不是单一风格，而是多种语言的组合。

- 哥特舞台底色：深紫、紫黑、橙金和珊瑚红。
- 拼贴构图：撕纸边、错位纸片、混合字体与不完全对齐。
- Risograph 质感：有限色板、网点和轻微套印错位。
- 哥特萝莉装饰：少量缎带、玫瑰、蕾丝或尖拱边框。
- 装饰应围绕舞台与任务状态服务，不能影响参数扫描效率。
- 参考：[Gothic](https://www.stylekit.top/zh/styles/gothic)、[Gothic Lolita](https://www.stylekit.top/zh/styles/gothic-lolita)、[Collage Art](https://www.stylekit.top/zh/styles/collage-art)、[Risograph](https://www.stylekit.top/zh/styles/risograph)。

### 6. 午夜本丸 JRPG

证明深色可以好看的独立方向。

- 葡萄深紫背景、橙黄色主要操作、青蓝信息状态、珊瑚红危险状态、米白正文。
- 紫黑边框代替纯黑，减少闷重感。
- 任务状态可借鉴队伍面板，日志可借鉴任务日志和战斗记录。
- 使用阶梯动画、闪烁选择箭头和硬边状态条，不使用霓虹泛光。

### 7. 其他实验主题

- 赛璐璐动画：明亮色块、清晰描边和动画分镜式状态反馈。
- 赛博和风 / 霓虹武士：适合特殊深色主题，需要严格控制发光面积。
- 蒸汽朋克：可用于仪表、进度与计时器，但避免把所有控件拟物化。
- 波普艺术 / 孟菲斯：适合撞色、几何装饰和强烈按压反馈。

## 可共享的主题地基

所有主题优先通过语义变量和少量主题修饰实现：

- 色彩：页面、面板、卡片、正文、弱文字、边框、主要操作、成功、警告、失败。
- 形状：圆角、边框宽度、硬阴影距离、控件高度。
- 排版：标题、正文、数字与日志字体。
- 纹理：和纸、网点、青海波、印刷错位、漫画网点等可选背景层。
- 动效：内容进入、按钮按压、选择提示、运行中、成功和失败。
- 装饰：只允许主题向预留装饰层添加内容，不侵入控件点击区域。

主题选择器最终应使用菜单或主题画廊，不再依靠一个按钮循环十几套主题。

## 布局研究结论

StyleKit 适合研究视觉语言，但 Showcase 多为落地页和组件陈列，不能直接解决自动化控制台布局。まあ丸需要从真实工具和游戏菜单中拆布局。

游戏 UI 也不是现成答案。游戏界面通常围绕人物、场景或物品画面安排信息，任务清单类应用又可能为了气氛主动降低信息密度；まあ丸必须优先保证参数、运行过程、异常和结果的阅读效率。游戏参考只用于局部状态表达、动效和未来的近侍舞台。

### 桌面端目标结构

1. 左侧任务导航：选择日课、活动、出阵和后勤任务。
2. 中央工作区：当前任务摘要、主要操作和日志。
3. 右侧本丸状态：资源、远征、锻刀炉、日课结果和内番。
4. 配置页使用左侧功能分组与右侧表单；窄屏改为顶部选择器。
5. 日志是任务反馈的一部分，不应被坐标和识别细节淹没；技术细节留在源码日志。

当前三列布局在宽桌面仍有价值，问题主要来自窄屏强行保留多列和内部滚动。响应式布局应改变结构，而不是单纯缩放。

### 手机端目标结构

1. 顶部状态与任务选择。
2. 当前任务卡和唯一主要操作。
3. 运行进度与精简日志。
4. 本丸统计、历史记录和配置通过分段视图或标签进入。
5. 避免并排小卡片、嵌套滚动区和需要横向拖动的任务导航。

### 近侍舞台设想

可以增加一个独立的“狐之助工作现场”，让 Agent 的运行状态拥有真正的像素动画，而不是把整个工具界面改造成游戏 HUD。

- 待命：呼吸、张望、打盹或整理卷轴。
- 导航与登录：赶路、开门、翻找入口。
- 远征：送队伍出门或举旗等待。
- 锻刀与手入：敲打、烧炉、搬工具或包扎。
- 出阵与活动：跑动、挥旗、战斗或躲避。
- 识别与等待：观察、举放大镜、翻书。
- 成功：盖章、撒花或举起成绩单。
- 警告与失败：停下、冒汗、展示提示牌。

舞台旁只显示一句当前动作和必要进度；详细日志、参数与错误处理仍留在工具工作区。游戏 UI 资料库可用于研究这个舞台的角色状态、转场、气泡和状态条。

#### 场景素材方案

游戏没有完整的本丸建筑全景，因此不做考据式复原。用现有景趣、天守阁轮廓、锻刀房、出阵地图和合战场外景拼出“属于本丸但不复制游戏画面”的像素空间。

第一阶段只制作三张主场景：

1. **本丸庭院**：以樱花景趣为主参考。前景保留室内木梁、障子与缘侧，外面是池塘、石灯笼、樱花、红桥和远山；远处可露出小型主屋或天守阁轮廓。用于待命、聊天、登录、签到、内番、盘点与任务完成。
2. **锻冶工房**：参考游戏锻刀房的炉火、铁砧、水槽、工具架和金属材料。用于锻刀、手入、刀解、合成与炼糖，通过替换角色手中道具和前景摆件区分动作。
3. **出阵之路**：结合卷轴地图、城门、道路、市街、原野与远山。默认显示从本丸门口通向远方的道路；活动、远征和普通出阵只替换路牌、天气、旗帜和远景，不需要分别绘制完整战场。

可选的后续场景包括市街、室内厅堂和地洞，但不阻塞第一版。

每张主场景拆为远景、中景、地面、前景框和交互道具层。樱花、云、炉火、烟尘、旗帜、灯光与天气由独立小图层或前端动画完成，避免重复绘制整张背景。

第一版角色动作可以压缩为待机、跑步、观察、工作、庆祝和翻车六组，再用放大镜、锤子、旗帜、卷轴、成绩单等道具组合覆盖具体任务。

### 值得继续研究的来源

- 信息密集工具：CI/CD 任务、下载器、队列管理器、自动化面板、监控台和带日志的桌面应用。重点观察任务列表、详情、实时输出、错误恢复和历史结果如何同时存在。
- 游戏 UI 资料库：[Interface In Game](https://interfaceingame.com/screenshots/) 和 [Game UI Database](https://www.gameuidatabase.com/) 只作为近侍舞台、角色状态、转场和局部组件参考，不作为主面板布局模板。
- 游戏启动器：任务/游戏库、最近活动和启动操作之间的层级。可先看 [PlayDock](https://playdock.app/)。
- JRPG 与游戏化任务工具：只借鉴任务状态、像素动画、气泡、选择反馈和主题氛围。[Questlog](https://www.getquestlog.com/) 信息密度过低，不适合作为まあ丸主布局；[MMO RPG UX 案例](https://www.johnnywhiteux.com/mmo-rpg-designs) 也主要服务未发布游戏画面，不直接套用。
- 自动化控制台：状态卡、立即操作、历史记录和告警的组织方式，重点看 Home Assistant 社区的移动面板，而不是照搬 Material 卡片墙。
- 任务运行器和下载器：队列、运行中、成功、失败、重试和技术日志之间的关系。
- 移动远控：首页只展示状态与高频操作，详细配置进入第二层；可搜索 robot control、home automation、remote task dashboard。

### 下一轮布局采样方式

不要继续收集整页风格截图。每个候选产品只截并标注以下五个画面：

1. 空闲首页。
2. 选择任务。
3. 任务运行中。
4. 任务失败并需要处理。
5. 手机端查看状态并远程停止。

每张图只记录三个问题：第一眼看到什么、主要操作在哪里、次要信息如何收起。积累到三至五个产品后再画まあ丸自己的线框图。

## 暂定优先级

1. 完成当前像素主题的基础组件和响应式布局。
2. 把主题变量、纹理层与动效参数整理成稳定接口。
3. 研究并确定桌面/手机布局线框。
4. 为近侍舞台定义任务状态与动画状态的映射，先用占位动画验证信息价值。
5. 制作浮世绘主题，验证换皮地基是否真的可复用。
6. 制作少女漫画或午夜 JRPG 主题，验证柔和与深色两个极端。
7. 最后制作剧团犬咖喱拼贴，允许它拥有最强的主题性格。
