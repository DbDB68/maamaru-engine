# 部队预设与出阵前准备 ROADMAP

## 一句话目标

把“编队”收缩成一个可复用的出阵前动作：按预设把指定成员（以后再加宝物）套进某支部队，验收到可继续后，才把控制权交给出阵或远征。

这不是复刻游戏的“部队编成”页，也不是再造一套实时本丸档案。

## 不准干偏的边界

- 不在面板里仿造游戏的五支当前部队；历史点名不冒充实时队伍。
- 不把“重新请求本地数据”叫做“刷新当前编队”。
- 不伪造游戏实例 ID。只保留快照内的 `observation_id`，并用当前可见属性尽量链接到具体一振。
- 不为了极少数完全同数值的同名刀放宽安全门槛；无法区分就说无法区分。
- 不恢复换人后 OCR 回读，除非以后有真实故障证明它必需。
- 不把选人的连续竖向列表假装成刀账的固定五行。
- 不绕过 `BattleMixin._safe_depart_stream` + `_confirm_departure`。套预设只是出阵前置，重伤、刀装和二次确认仍走统一安全链。
- 没打开、没取样的装备/宝物页不猜坐标、不猜绑定规则、不先写点击流程。

## 目标用户流

### 普通用法

1. 在“部队预设”里选目标部队和 1～6 号位成员。
2. 出阵/活动/远征的“使用部队”可直接选这套预设。
3. 任务开始后先套预设；失败则停在出发前，明确说卡在哪个位置。
4. 套好后再进入玩法原有的安全出发链。

### 任务流用法

增加独立的“套用部队预设”积木，供需要多步复用或中途换队的工作流使用。它与玩法下拉框调用同一个后端动作，不另造实现。

## 数据契约

### 刀剑的相对实例

预设槽位保存刀账快照中的 `observation_id` 和一份可见指纹，不只存名字。指纹可用字段：

- 刀种目录 ID、普通/极形态；
- 刀剑等级、乱舞等级；
- 生存上限；
- 打击、防御、机动、冲力、侦察、隐蔽、必杀等当前成长值；
- 显现日期只在刀账内作辅助指纹，编队/选人页看不到时不强求。

疲劳和当前生存会随时变化，只作状态，不作实例身份。普通刀以生存上限和侦察值区分同名实例，刀剑等级只允许上涨；打击等六项随养成变化，不单独当身份。耕作前后生存/侦察若涨了，只有内番表的数值与当前观察吻合、其余六项完整一致且旧值能唯一落到刀账一振时，才保留对应证据供轮换后使用。同名或旧值撞车保持 `ambiguous`，不能凭刀名把 +1 加给某一振。完整刀账中最终仍需唯一吻合；对不上就提示更新档案。

### 宝物

宝物按独立实例建模，预留：本地观察 ID、名称/种类、强化状态、当前所属刀剑、可用状态、观察时间和来源。

“所属刀名”在真机证明前只解释为当前装备者，不预设临时占用、可换装或永久绑定。

### 刀装与御守

不建独立实例库。如后续预设需要，只保存装备策略（例如不处理/自动装备/需要御守），具体安全处理仍由现有出阵链负责。

## 施工阶段

### 阶段 0：收口契约，删掉伪语义

- [x] 把面板定位从“当前编队复刻”改成“部队预设”。
- [x] 移除历史一至五队冒充当前队伍的展示和误导性“刷新档案”。
- [x] 清理“换完回读验收”、`verification_failed`、`formation.member_ensured` 等与当前真实行为不符的前端文案/契约。
- [x] 定稿预设数据版本和旧 `custom_formations.json` 的无损兼容方案。

**验收：** 玩家只会看到“我想套用什么队”，不会看到一份装作实时的旧队伍。

### 阶段 1：让预设真正成为玩法输入

- [x] 收拢现有“玩法部队下拉框选预设”的半成品接线，先覆盖普通出阵/活动/演练。
- [x] 把同一入口接到远征，不在远征另写一套换人。
- [x] 增加“套用部队预设”工作流节点，与玩法下拉框复用同一后端执行器。
- [x] 开工前一次性检查六槽身份是否齐全、是否存在同位刀冲突、档案是否可用；检查不过时不点第一下。
- [x] 逐槽套用仍可能因游戏占用状态中途失败；不盲目回滚，如实报告已换/未换的槽位，且绝不继续出发。

**验收：** 同一套预设可从玩法设置和任务流调用；远征/出阵在预设未套完时不会出发。

### 阶段 2：六槽固定 ROI 和当前队伍最小读取

- [x] 将部队编成页 1～6 号位的「位置号＋刀名」、等级块、属性带和徽章等读取区域注册进开发工具；不要求单独框空位。
- [x] 由老大使用运行帧在开发工具中逐格框定；框定值回收成默认 ROI 前跑离线帧验证。
- [x] 名字框读到「位置号＋刀名」时先剥离已确认的位置号再认刀；只读到位置号时作为空位候选，仍需核对同槽其他成员证据，矛盾或识别不足时记 `unknown`，不能把漏读刀名当空位。
- [x] 读取仅服务“已在正确位置则跳过”和执行报告，不重建前端实时五队。
- [x] 以完整刀账为候选池，当前槽只在可见指纹唯一时链接到候选 `observation_id`。
- [ ] 用实际任务执行截图验收：同一振零点击、歧义或旧档案不得零点击，并记录边界值。

### 阶段 3：选人列表改成单向搜寻

- [ ] 保留“列带 OCR＋刀名 y 锚点”，增加乱舞/生存/属性列带；不设置固定第几行 ROI。
- [ ] 先由完整刀账证明目标可见指纹在本丸内唯一；档案本身已歧义时不开选人页。
- [ ] 列表从顶部单向小步滚动，相邻视口至少重叠一行；使用行指纹确认真的向下移动。
- [ ] 目标在当前视口完整显示、指纹完全吻合且连续两帧成立时，当场点“决定”。
- [ ] 上下边缘的半截行不点；小幅调整到视口中部后再读。
- [ ] 只在明确到底仍没找到时报 `not_found`。删除“先扫完全表→再反向找回目标页”的回头路。

**真机停工点：** 需要筛选后列表的顶部/中段/底部运行帧，并包含至少一张上下边缘有半截行的帧。

### 阶段 4：装备与宝物科研

- [ ] 先从部队编成页打开一振刀的装备页，使用脚本运行帧通道保存完整帧；记录页面层级和安全返回路径。
- [ ] 分别查看刀装、御守、宝物的入口和列表形态，不认定它们共用同一选择器。
- [ ] 宝物至少完成“未装备→装给 A→查看所属→尝试卸下/换给 B”的可回退实验，再定临时占用或绑定契约。
- [ ] 宝物列表若有当前所属刀名，将其作为实例观察字段；不在实验前解释为永久绑定。
- [ ] 根据真帧才注册装备页/宝物页 ROI，并补充候选唯一性、占用和失败恢复测试。
- [ ] 出阵预设接宝物实例；远征是否需要装备继续按真实玩法需求决定，不强行绑定。

**真机停工点：** 装备页没有被真实打开、宝物所属规则没有通过可回退实验确认之前，本阶段只记录证据，不写自动点击。

## 每一阶段的统一验收

- 纯逻辑单元测试：唯一/歧义/过期指纹，中途失败，任务流与下拉框共用契约。
- 识别改动：除测试外必须有同源运行帧、边界值和实际执行截图；滑动未确认时只能 `stalled`。
- 前端改动：宽屏、窄屏和手机布局实际检查，不制造嵌套滚动。
- 完整校验：根目录前端构建、Python 全量测试、`compileall`、`git diff --check`。
- 只提交当前阶段的文件，不顺手开下一阶段。

## 开工顺序

1. 先完成阶段 0，把产品语义和兼容边界收干净。
2. 完成阶段 1，让现有名字＋等级安全链先服务真实出阵/远征，但不对歧义候选放行。
3. 到阶段 2 时暂停写算法，由老大在开发工具框六槽 ROI，回收真帧后再继续。
4. 完成阶段 3 的单向动态搜寻，用属性指纹解决大部分同名同级。
5. 阶段 4 只在真机打开装备/宝物页后启动。
